# 小红书海报裁切定稿规则

> **Agent 标 `posterBox` 前必读。** 与 [`xiaohongshu-vision-agent.md`](xiaohongshu-vision-agent.md) 配合使用。  
> 裁切 JS 只执行坐标、不做语义判断；**准不准完全取决于 Agent 是否按本节规则读图标框。**

---

## 核心原则（必须遵守）

0. **目的优先：从 slide 里切出本场活动的矩形海报，边缘必须准**  
   海报一般是独立矩形主视觉。标 `posterBox` 就是标这块矩形的四边外缘，使裁切结果完整、干净、比例正确。

1. **每张 slide、每场活动单独分析**  
   **同一笔记内各张 slide 版式可以完全不同**（不能假设「这个帖子统一左文右图」）。每张图从零开始看排版，再标框。

2. **`posterBox` = 海报本体外缘的最终裁切区域**  
   四边贴在目标海报的底色/边框截止线，不是 slide 白条、不是说明区、不是邻场残影、不是页眉黄条。

3. **每场坐标独立，禁止套模板**  
   - 禁止把 slide01 的 box 复制到 slide06  
   - 禁止同一页多个活动共用一组 `x,y,w,h`（如全写成 `626,289,410,433`）  
   - 禁止按「上行/下行固定比例」猜位置（如 `y=0.23h` / `y=0.62h`）  
   - 禁止按城市/账号假设统一 `x`（如「西安都是 x≈640」）  
   - 旧版 `poster-box-measured.json`、全图扫描猜框脚本**已废弃**，不要复用

4. **保留海报原始宽高比**  
   `extract` 只做 `sharp.extract`，**不缩放**。若 `w:h` 与真实海报不一致，成品要么切掉内容，要么看起来像「被拉扁/拉长」。  
   同一张 slide 上两场活动的 `w`、`h` **可以且常常应该不同**。

5. **宁可 skip，不可硬裁**  
   框不干净、会带进说明文字或邻场 → 不写 `posterBox`，走文字封面。

6. **列表帖左栏海报仍算海报**  
   本地宝等「左图右文」每条活动左侧约 190×280 的竖图，是该场宣传主视觉，**应标 `posterBox`**（不要因宽 <25% 就 skip）。  
   仅 skip：纯文字、时间表、横条 banner、极小装饰 icon。

## 标框流程（每次抓取 / 重裁都做）

```
抓取 → webp + images-jpg/
标框 → 根据版式复杂度动态读图 → 每场 posterBox（%→px）→ skip 纯文字/时间表
全部标完 → extract（产出 posters/）→ 抽查成品图 → 必要时返修 → import
```

**不跑**：`preview-poster-boxes.js`（红框）、`create-poster-contact-sheet.js`（拼大图）。

### 首次裁切质量硬流程（第一次抓取也必须做到）

首次抓取不是先粗切再等用户发现问题。每一次新笔记写 `posterBox` 时，都必须一次性按交付标准做完：

1. **先确认原图尺寸和坐标系**  
   读 `images-jpg/XX.jpg` 只是为了肉眼标框，坐标必须相对 `images/XX.webp`。写第一张前先确认两者尺寸一致，不能默认所有图都是 1080×1443。
2. **先找本场主视觉，再量坐标**  
   每场先判断海报在哪：左栏、右栏、上行、下行、单图、双图、多宫格。只有确认是本场独立矩形主视觉后，才写 `posterBox`。
3. **四边贴海报本体，不贴信息区**  
   `x` 贴海报左边，`y` 贴海报上边，`w/h` 到海报右下边缘为止。不能包含黄标题条、时间地点正文、票价说明、页眉合集标题、邻场内容或大块 slide 背景。
4. **下行活动重点量真实 `y`**  
   同页上下两场时，下行海报经常在整图靠下位置。必须按原图真实上边缘量，不能凭“上下两半”估成中间坐标。
5. **右栏活动重点量真实 `x`**  
   右侧海报的左边缘通常比正文区更靠右。`x` 宁可贴海报边缘，也不要把正文空白或说明文字裁进去。
6. **白底/浅色海报按外框或墨水边界收紧**  
   白底设计海报不能把 slide 白底一起裁进去；有圆角、阴影、边框时，按可见海报外缘裁。
7. **同一页多场也要逐场量**  
   同页上行、下行或左右两场的 `x/y/w/h` 可以接近，但不能直接复制。至少要重新看每场海报的上边、下边和实际宽高。
8. **拿不准就不写 `posterBox`**  
   多宫格归属不清、横条太矮、边界会夹文字或邻场时，直接跳过海报，走文字封面。坏海报比没海报更糟。
9. **写完一组就马上 extract 抽查**  
   不要整城全部写完才发现系统性偏移。每个新笔记至少抽查上行、下行、右栏、版式突变页；首次抓取也必须看 `posters/*.jpg` 成品图。
10. **抽查合格才允许 import**  
   入库前必须确认成品裁图标题、日期、脚标完整，且没有夹入正文、邻场或大块背景。

### 重裁返工硬流程（用户反馈切坏时必须执行）

当用户说「重来」「切坏了」「底部切掉」「逐张分析」等，视为上一轮 `posterBox` 不可信，必须按下面闭环重做：

1. **先清掉目标笔记旧 `posterBox`**  
   不在坏坐标上局部修补。先删除目标城市/笔记里上一轮坏框，并立即写 `vision-slots.meta.json`，避免 extract/import 继续复用旧坏图。
2. **确认坐标系尺寸**  
   先看 `images/XX.webp` 与 `images-jpg/XX.jpg` 尺寸是否一致。实际坐标一律相对 `images/XX.webp` 原图，常见但不能假设为 1080×1443。
3. **重新读原图，不读旧裁图定坐标**  
   旧 `posters/*.jpg` 只能用于发现问题，不能反推坐标。标框必须回到 `images-jpg/XX.jpg` 原图逐张看。
4. **按行真实量 `y`，尤其下行活动**  
   同页上下两场时，下行海报常在整图很靠下的位置。不要按视觉印象把下行写成中部坐标；必须贴住下行海报真实上边缘，避免从两场中间开始切。
5. **按列真实量 `x`，尤其右栏活动**  
   右侧海报常明显靠右，不要为了保说明区而把 `x` 写得过小。左边缘要贴海报本体，不能夹进正文空白。
6. **只给边界清楚的海报写框**  
   如果边界会夹说明文字、上一场/下一场、页眉、水印或大块 slide 背景，宁可不写 `posterBox`，走文字封面。
7. **extract 后必须直接读 `posters/*.jpg` 抽查**  
   至少抽查：上行 1 张、下行 1 张、右栏 1 张、版式突变页 1 张、用户点名问题页。发现夹上一场、切底、切标题、白边过大，立刻回原图改坐标并重新 extract。
8. **抽查通过后才 import**  
   import 不是验收步骤。只有成品裁图已经肉眼通过，才允许入库刷新审核台。

返工时可以使用脚本批量删除/写入 JSON，但脚本只能执行 Agent 已经读图决定的坐标；禁止让脚本判断海报位置。

## 如何分析「海报在哪」

**没有固定版式，也没有帖子级版式。** 每一张 slide、每一场活动都要单独在图上找「本场对应的那块矩形海报」。

下面只是**偶尔出现的排版现象**（帮助定位），**不是版式分类表**——看到现象后仍要在当前图上重新量四边，不能把某一期的坐标当标准答案：

| 你可能看到的现象 | 标框时注意 |
|------------------|------------|
| 说明文字在一侧、彩色海报在另一侧 | 只框海报矩形，说明区排除 |
| 同页上下各一场 | 上下各找矩形，分别量 |
| 整页几乎一张大海报 | 框海报外缘，排除页眉 |
| 多宫格 / 日历 | 只框本场那一格 |
| 白底设计海报 | 按外边框/阴影定界，不能穿到 slide 白底 |

**复盘示例（勿当模板）：** 西安笔记 `6a2670f50000000021015c86` 曾 14 场共用一组坐标导致大面积坏裁切；修正后每场单独 `posterBox`，`w×h` 互不相同。其他城市、其他 slide 必须重新读图。

**复盘示例（勿当模板）：** 北京 / 天津 / 重庆曾因没有回到原图逐张量，出现三类典型坏图：北京下行活动把 `y` 写到两场中间，导致底部切残；天津右栏海报把 `x` 写得过左，夹进正文空白且漏真实海报边；重庆底部活动版式不固定，沿用上半页坐标会夹进上一场。修正方法是先清旧框，按原图真实边缘重新量，再 extract 后逐张读成品图返修。

## 精度标准（好裁切 vs 坏裁切）

| 必须满足 | 视为坏裁切 |
|----------|------------|
| 海报标题、日期、脚标完整在框内 | 裁掉下缘日期 / 上缘主标题 |
| 四边贴海报外缘，不含 slide 底纹 | 左上露 slide 白边或浅蓝条 |
| 只有本场主视觉，无邻场内容 | 带进 ✅ 闹钟、地图、票价、邻场橙条 |
| 输出比例与海报一致（瘦高就瘦高） | 14 张裁出来几乎一样宽高的「模板感」 |
| 景区照、现场照、展品照也可当封面 | 把说明文字区当海报 |

## posterBox 格式

```json
"posterBox": {
  "slide": "05.webp",
  "x": 647,
  "y": 328,
  "w": 398,
  "h": 532
}
```

- `x,y,w,h`：**整数像素**，相对该 `slide` 原图左上角  
- `slide` 与 `vision-slots` 条目的 `slide` 字段一致  
- 每场活动单独一组；`w/h` 反映该海报真实比例

## 裁切后与入库

- `node scripts/extract-xhs-weekly-events.js <笔记目录>` → 有 `posterBox` 时写 `posters/*.jpg`
- 直接读关键 `posters/*.jpg` 抽查：标题、日期、脚标完整；不夹说明文字、邻场或大块 slide 背景
- 抽查失败：回到原图改 `vision-slots.json` → 重新 `extract` → 重新抽查
- 抽查通过：然后 `import-xhs-events-to-review.js`
- **不跑**红框预览、不拼 `posters-contact-sheet.png`

有海报入库后：`event-image-compose.js` 按海报比例合成 4:3 封面（瘦高左图右文 + 标题 CTA），见封面规则文档。
